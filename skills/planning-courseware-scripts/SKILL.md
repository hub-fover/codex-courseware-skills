# 课件脚本策划

## 原则

先建立全局内容基准，再连续完成全部脚本，最后只做一次统一内容核对。分批是内部组织方式，不是用户确认门槛。

**必须先完整读取 [脚本与输出契约](references/script-contract.md)。**

## 工作流程

1. 读取全部输入，标明哪些是事实源、视觉参考和课程元数据。视觉参考不自动成为事实源。
2. 内部建立术语、公式、变量、单位、坐标约定、适用条件、退化条件和来源映射基准。保留原文、修订、理由和可定位来源；不将无依据的改写冒充为源内容。
3. 按知识先修关系和密度自动确定页数，生成完整目录。每页只解决一个核心问题。
4. 从第 1 页开始，每 5 页一批连续生成详细脚本；最后一批可少于 5 页。每页严格使用契约中的 13 个字段。
5. 每批完成后只做结构检查，不请求用户确认。可用验证器的 `--allow-partial` 检查已完成的连续前缀。
6. 全部批次完成后，仅执行一次统一内容核对：覆盖来源、术语、公式、变量、页码、重复页、知识跳跃、13 字段、占位符和超范围内容。最终再运行不带 `--allow-partial` 的完整验证。
7. 输出完整目录、全部详细脚本批次、统一核对报告和待确认问题清单，然后停止，等待用户最终统一确认。

## 暂停门槛

只有事实源冲突、关键内容缺失，或科学性问题无法可靠判断时才提前暂停。普通术语统一、版式选择、页数拆分和可由可定位权威来源解决的明确错误，由本 Skill 自动处理并留痕。

## 范围边界

脚本统一确实完成后必须停止。不得生成预览图、PPT、Research visual 指令或网页端执行包，也不得因“顺手预览”、“帮助性额外交付”或时间富余进入出图。后续出图是独立任务，可由 `producing-research-visual-pages` 处理。

## 验证器

```powershell
python scripts/validate_courseware_markdown.py --outline <目录.md> --scripts <批次文件1.md> <批次文件2.md>
```

机械验证不代替最终的语义、教学与科学性核对。
